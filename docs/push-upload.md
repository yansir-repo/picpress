# 推送上传（Push）：需求与接口

> 给实现者的说明。这份文档只讲**要做什么、做到什么算对、和服务端怎么对接**；怎么写由你定（Go 侧是唯一真相，前端只编排和渲染，这条沿用 README）。
> 状态：待实现。版本：1。

## 1. 为什么做

PicPress 今天是「拖进来、压小、存到本地」。我们要让它再多一个出口：**把压好的文件，按用户自己的文件夹路径，推到一个云端地址**。

典型场景：一个做网站的团队要向客户收资料（产品图、证书扫描、案例图、视频）。客户不会、也不该上传网页、发邮件、传网盘。我们给客户一个 PicPress 和一份**配置文件**，客户双击导入配置，把自己的文件夹拖进去，文件就在本机压缩、自动传给我们。传到一半断网也没关系，重开会接着传，传过的不会重复。

### 边界（很重要）

- **PicPress 是通用工具。它不认识任何项目、任何资料清单。** 没有「投放区」、没有「这一项资料」、没有账号。**要传哪些资料，由我们用文字告诉客户；客户的文件夹怎么命名、怎么放，PicPress 原样保留。**
- 上传是**可选**的：没导入配置时，PicPress 的行为和今天完全一样（压缩、对比、保存到本地）。
- 服务端的事（签发凭证、判断「资料齐没齐」、通知项目经理）**不在这里做**。PicPress 只负责：本机压缩、按路径推送、断点续传、去重、如实报告。

## 2. 一句话流程

1. 客户双击配置文件，PicPress 导入，显示「已连接：&lt;名称&gt;」。
2. 客户把一个或多个文件夹（或文件）拖进窗口。
3. PicPress 扫描，显示「将要上传」的清单（几个文件、多大、哪些会被跳过及原因），客户确认。
4. 本机压缩 → 逐个推送（分片、重试、续传）→ 每一批完成后留下一份「批次清单」。
5. 结束时显示结果：已送达 N / M、重复跳过、跳过（原因）、失败（可重试），并可一键复制成文字，发给我们。

## 3. 功能需求

### F1 导入配置

- 配置文件扩展名 `.picpress-config`（JSON，格式见 §4）。导入方式三种：**双击文件**（注册文件关联）、**拖到窗口上**、菜单「导入配置…」（⌘I / Ctrl+I）。
- 导入成功后弹出确认卡片：显示 `label`、`credentialsUrl` 的主机名、可选的 `notice` 文字；用户点「连接」才生效。
- 设置里能看到当前的连接（名称、主机、状态），可以「移除」。v1 只需要**一个**活动连接，导入新配置会替换旧的（先确认）。
- **配置里没有任何 S3 密钥。** 项目令牌（`token`）存进系统钥匙串（macOS Keychain / Windows 凭据管理器），不写明文文件、不进日志。
- 配置格式不对、版本不认识、令牌已失效，要给能照做的中文提示（例如「这份配置的版本比你的 PicPress 新，请更新 PicPress」），不要只报错码。

### F2 换取并刷新上传凭证

PicPress 用 `token` 向 `credentialsUrl` 换**短期、只能上传**的 S3 凭证（接口见 §5）。要求：

- 开始上传前换一次；凭证剩余不足 5 分钟、或某次请求返回 403 / `ExpiredToken` 时自动再换，**对用户透明**，同一次请求只重试一次。
- 凭证只放内存，不落盘、不进日志。
- 换凭证失败时按原因分别提示：401 →「这份配置已失效，请联系给你配置的人」；网络错误 → 自动退避重试并显示「正在等待网络」；429 / 5xx → 退避重试。

### F3 另一种连接方式：手填 S3 兼容地址（通用能力，也是开发联调用的）

设置里提供「自定义 S3 兼容地址」：endpoint、bucket、前缀、access key、secret、可选 session token、区域（默认 `auto`）。它和 F1 共用同一套上传管线，区别只是凭证来源。**对客户不展示**（只在设置的「高级」里）。

### F4 拖入、扫描、确认

- 拖入文件夹或文件（可一次多个）。文件夹递归扫描。
- **云端路径规则**：`<前缀><拖入的顶层名>/<相对路径>`。拖入文件夹 `证书扫描`，里面有 `a/b.jpg`，云端键是 `<前缀>证书扫描/a/b.jpg`。直接拖入单个文件，键是 `<前缀><文件名>`。**保留用户的命名和层级，不要改成英文、不要加时间戳、不要改扩展名**（压缩改变格式时除外，见 F5）。
- 扫描完先显示「准备上传」面板，**用户确认之前不发任何网络请求**（换凭证除外）：
  - 分类计数：图片 / 文档 / 视频（只传抽帧）/ 跳过；
  - 原始总大小、预估压缩后大小；
  - 「跳过」的逐条原因（可折叠）；
  - 超过配置里 `limits` 的任意一项时，**硬拦住**并说明超了什么；超过 500 个文件或 1 GB 时，高亮并要求二次确认（这两个数写成常量，别散落）。
- 取消、关闭面板，什么都不留在云端。

### F5 压缩

- 图片按**当前设置**（输出格式、质量、尺寸）压缩，沿用现有的压缩管线，不另写一套。
- 压缩后比原图还大：上传原图（并在元数据里标 `compressed=false`）。
- 带文字的图（证书、参数表）可能被压糊：设置里加一个预设「文字图」（高质量 PNG 或 WebP），用户可以按拖入的批次选择预设。**不要**根据文件夹名猜。
- HEIC / HEIF 解码后按设置输出（已支持）；GIF 只取第一帧（沿用现状）。
- 压缩失败（损坏、0 字节、不可读）：该文件记为「失败」，原因进报告，**不中断整批**。

### F6 非图片文件

- 文档类（`pdf docx doc xlsx xls pptx ppt csv txt md json html`）**原样上传**，不压缩，受 `maxFileBytes` 限制，超了跳过并说明。
- 其他格式（`psd ai eps raw` 等）：**跳过并如实列出**，原因写「格式暂不支持」。**绝不能悄悄丢掉。**
- 视频不走这里，见 F7。

### F7 视频：只传抽帧，不传原片

- 识别视频（`mp4 mov m4v avi mkv webm mts`）后，**在本机抽帧**，**原片不上传**，界面明确写「原片不会上传」。
- 抽帧结果上传到 `<相对路径>.frames/` 下：
  - `frame-01.jpg … frame-NN.jpg`：均匀取 `video.frames` 张（默认 12；时长很短时可以更少），避开开头结尾各 2%；长边不超过 1280，JPEG 质量约 78；
  - `contact.jpg`：联系表（4 列网格，帧上不需要文字）；
  - `meta.json`：`{ durationSec, width, height, fps, codec, sizeBytes, originalName, originalPath, frames: [{ file, atSec }] }`。
- 实现自由（内置 ffmpeg 的 LGPL 构建、系统 API 都行），但必须：**离线可用**、典型 1 分钟视频在几十秒内完成、不触网。许可证要核对后写进 README。
- 读不出来（损坏、加密）：记为失败并说明，不影响其他文件。

### F8 上传：分片、重试、续传、去重

**凭证是「只能上传」的：它不能 HEAD / LIST / GET / DELETE，也不能 ListParts。** 这决定了下面的设计，**不要依赖任何读操作**（验收里会检查）。

- 并发默认 3，可在设置里调（1–6），可限速。
- 小文件用单次 PUT；**大于 16 MB** 用分片上传（每片 8 MB）。
- 每个文件**独立**重试：指数退避，最多 6 次（1、2、4、8、16、32 秒，加抖动）；可重试的是网络错误、5xx、429；403 先换凭证再试一次；400 / 其他 4xx 不重试，记为失败。
- **本机日志（journal）是「传过什么」的唯一依据**：每个目标（配置名 + 前缀）一份，存应用数据目录，记录每个云端键的 `originalSha256`、压缩参数、上传后大小、时间、分片进行到哪（`uploadId` 和已完成分片的 ETag）。
  - 同一云端键、同一 `originalSha256` 和同样的压缩参数：**跳过**，计入「重复跳过」；
  - 同一云端键、内容不同：覆盖上传（v1 不做版本），更新日志；
  - 日志丢了：会重复上传，**可接受**（服务端会按哈希去重），但要在界面上不吓人；
  - 关闭应用、断电、断网后重开：**自动从日志恢复**，已完成的文件不重传，分片按已完成的分片接着传；`NoSuchUpload` 就重开这一个文件。
- **压缩产物在上传完成前要留在临时目录**（续传需要字节一致，压缩本身不保证每次相同）。日志记临时文件路径；临时文件不见了，就重压并从头传这一个文件。
- 校验：每次 PUT 带 `x-amz-checksum-sha256`（对**上传的字节**），让服务端核对；若实测目标不支持，退回只写元数据 `sha256`，并在代码里写明。
- 对象元数据（`x-amz-meta-*`）：`original-sha256`、`original-size`、`source-path`（相对路径）、`compressed`（true/false）、`params`（如 `fmt=webp;q=82;max=2048`）、`device-id`、`batch-id`、`picpress-version`。`Content-Type` 要对。
- **取消**时对进行中的分片上传发 `AbortMultipartUpload`；暂停不发。
- 网络断开：自动暂停并显示「等待网络」，恢复后继续，不要把一堆文件都标成失败。

### F9 批次清单

服务端会靠它知道「到了什么」。每个批次的清单是**一个对象**，放在同一前缀下的隐藏目录：

`<前缀>.picpress/batches/<batchId>-<seq>.json`

- 触发：每 50 个文件、或 60 秒内有新结果、或队列清空 / 暂停 / 取消 / 失败时各写一份；`final: true` 只在整批结束时出现。
- **顺序**：清单里列的文件必须**已经上传成功**之后，才能写这份清单。
- 格式：

```json
{
  "v": 1,
  "batchId": "b-20261021-0001",
  "seq": 3,
  "deviceId": "mac-li",
  "appVersion": "1.4.0",
  "sentAt": "2026-10-21T11:31:20+08:00",
  "roots": ["证书扫描", "案例"],
  "files": [
    { "key": "案例/a.jpg", "size": 123456, "sha256": "…", "originalSha256": "…", "originalSize": 456789, "status": "uploaded" },
    { "key": "案例/b.jpg", "size": 120000, "sha256": "…", "originalSha256": "…", "originalSize": 400000, "status": "skipped-duplicate" }
  ],
  "skipped": [
    { "path": "产品/封面.psd", "reason": "unsupported" },
    { "path": "产品/大文件.pdf", "reason": "too-large" }
  ],
  "failed": [{ "path": "案例/坏图.jpg", "reason": "decode-error" }],
  "videos": [
    {
      "path": "车间视频/a.mov", "durationSec": 42.1, "width": 1920, "height": 1080,
      "frames": ["车间视频/a.mov.frames/frame-01.jpg"], "contact": "车间视频/a.mov.frames/contact.jpg", "originalUploaded": false
    }
  ],
  "final": false
}
```

- `reason` 取值固定为：`unsupported`、`too-large`、`empty`、`hidden`、`symlink`、`name-conflict-renamed`、`decode-error`、`read-error`、`network`、`auth`。需要新增先改这份文档。

### F10 路径与文件名

- **统一规整成 Unicode NFC**（macOS 文件名常是 NFD，同一个字符串在两个平台上会不一样）；`\` 换成 `/`；去掉控制字符；去掉末尾的空格和点（Windows 不允许）。
- 键长不超过 1024 字节（UTF-8），单段不超过 255 字节；超了截断并加短哈希，写进 `skipped` / `name-conflict-renamed` 说明。
- 规整后两个文件重名：后者加 ` (2)`、` (3)`，并在报告里列出对应关系。
- **默认忽略**：`.DS_Store`、`Thumbs.db`、`desktop.ini`、`._*`、所有以 `.` 开头的文件和文件夹、符号链接、空文件夹、0 字节文件。忽略的要计入「跳过」并说明，不是静默。
- 云盘占位文件（iCloud「优化存储」、OneDrive「仅在线」）读不到内容时，提示「这个文件还没下载到本机」，记为跳过，不当失败。
- Windows：支持长路径（`\\?\`），遇到保留名（`CON`、`NUL`…）按 F10 规整。

### F11 界面

- 导入配置前：和现在一样。导入后：窗口顶部一条状态「已连接：&lt;label&gt;」，拖入后多出「准备上传」面板和「上传」视图。
- 「上传」视图：总进度、按顶层文件夹的进度、逐文件状态（等待 / 压缩中 / 上传中 / 完成 / 重复跳过 / 跳过 / 失败）、暂停 / 继续 / 取消、对失败项「重试」。
- 结束摘要（可「复制为文字」，要能直接粘到聊天里）：
  `已送达 238 个（共 247 个）；重复跳过 7；跳过 2（.psd 暂不支持）；失败 0。视频 3 个只传了抽帧。`
- 所有错误信息是中文、说清下一步该做什么。
- README 里「全程本地：不上传、不联网」要改成：**默认全程本地；只有导入配置并确认后才会上传，且只上传你拖进来的文件**。

### F12 安全

- 令牌只存系统钥匙串；凭证只在内存；日志里不出现令牌、密钥、完整的预签名地址。
- 只走 HTTPS，校验证书，不跟随到别的主机的重定向。
- 导入配置时显示 `credentialsUrl` 的主机名；配置里的 `limits` 是**上限**，PicPress 不允许被配置放宽到比内置硬上限更大（内置硬上限：单文件 200 MB、单批 5000 个文件、20 GB）。
- 本机时间偏差：S3 签名依赖本机时间。遇到 `RequestTimeTooSkewed`，提示「你电脑的时间不准，请校对系统时间」，不要报成网络错误。

### F13 平台与分发

- **新增 Windows 10 / 11（x64）**。现在只有 macOS（README 写的是 macOS 12+）；我们的客户多数用 Windows，不做 Windows 这个功能等于没做。
- 两个平台都要**签名**：macOS Developer ID + notarize；Windows Authenticode。否则客户第一次打开就是「无法验证开发者」，很多人会停在这一步。
- 双击 `.picpress-config` 要能直接用 PicPress 打开（两个平台都注册文件关联）。
- 安装包要小、能离线安装；v1 不要求自动更新，但要求版本号在界面里看得到，配置里的 `version` 高于应用支持的版本时给出明确提示。

## 4. 配置文件 `.picpress-config`

JSON，UTF-8：

```json
{
  "version": 1,
  "label": "MZ-007 阳光先生",
  "credentialsUrl": "https://grill-me.yansir.workers.dev/api/picpress/credentials",
  "token": "pp_live_…（不透明字符串）",
  "notice": "资料传完后告诉我们一声。视频不用传原片，PicPress 会自己抽帧。",
  "limits": { "maxFiles": 3000, "maxTotalBytes": 4294967296, "maxFileBytes": 52428800 },
  "video": { "frames": 12 }
}
```

- `version`（必填，整数）：不认识就拒绝导入并提示更新。
- `label`、`credentialsUrl`、`token`（必填）。其余可选，缺省用内置默认值。
- **没有**：S3 密钥、资料清单、投放区、项目的任何业务信息。

## 5. 服务端接口：换凭证（我们实现，你只管调用）

`POST {credentialsUrl}`
请求头：`Authorization: Bearer {token}`、`Content-Type: application/json`
请求体：`{ "deviceId": "mac-li", "appVersion": "1.4.0", "os": "darwin-arm64" }`

成功 `200`：

```json
{
  "endpoint": "https://<account>.r2.cloudflarestorage.com",
  "region": "auto",
  "bucket": "inbox",
  "prefix": "MZ-007/inbox/",
  "accessKeyId": "…",
  "secretAccessKey": "…",
  "sessionToken": "…",
  "expiresAt": "2026-10-22T11:31:20Z"
}
```

- **`prefix` 以 `/` 结尾**，所有键都必须在它下面：PicPress 拼键时用它，不要自己猜。
- 凭证是**只能写**的：只允许 `PutObject`、`CreateMultipartUpload`、`UploadPart`、`CompleteMultipartUpload`、`AbortMultipartUpload`，且只在这个前缀下。**其余一切都会 403**。
- `401`：令牌已失效；`403`：这个设备不被允许；`429`：稍后重试（带 `Retry-After`）；`5xx`：可重试。
- `deviceId`：首次运行生成随机 ID（存应用数据目录），在界面的「关于」里可以看到，换了电脑就是新的。

用 S3 SigV4 签名（`service=s3`、`region=auto`），`X-Amz-Security-Token` 带 `sessionToken`。

## 6. 开发与联调

- 本地用 MinIO（或任意 S3 mock）起一个桶，并**配成只允许上述 5 个操作**；写一个几十行的假凭证服务（返回 MinIO 的临时凭证）。我们会另外给一个真的测试环境。
- 必须有一个**会拒绝一切读操作的测试**：整个上传流程跑完，mock 端记录的请求里不应出现 `GET` / `HEAD` / `ListObjects` / `ListParts` / `DELETE`（`AbortMultipartUpload` 的 `DELETE` 除外，仅在取消时）。

## 7. 验收清单

每一条都要有自动化测试或可复现的手工步骤：

1. 导入合法配置成功；坏格式、版本过高、令牌 401，各自给出正确的中文提示。
2. 拖入 1000 个文件的多层中文文件夹，路径在云端完全一致（NFC、空格、括号）。
3. **再拖一次同一个文件夹：0 个上传，全部「重复跳过」。**
4. 改了其中一张图再拖：只传这一张。
5. 上传中途强制退出，重开：从日志恢复，已完成的不重传。
6. 上传中途断网，再恢复：自动暂停、自动继续，没有一堆失败。
7. 一个 100 MB 的 PDF，分片上传到一半退出，重开后接着传。
8. 凭证过期（把有效期调到 30 秒）：上传过程中自动换新，用户无感。
9. 令牌被作废：显示「配置已失效」，不无限重试。
10. 拖入 `.psd`、`.ai`：出现在「跳过」里并写明原因。
11. 拖入视频：云端只有 `.frames/`（帧、联系表、`meta.json`），**原片没有被读取到网络**，界面写「原片不会上传」。
12. 规整后重名的两个文件：后者带 ` (2)`，报告里有对应关系。
13. `.DS_Store`、隐藏文件、符号链接、空文件夹、0 字节：不上传，且计入「跳过」。
14. 超过 `limits`：硬拦住；超过 500 个文件或 1 GB：二次确认。
15. **全程没有任何读操作**（见 §6）。
16. 批次清单在它列出的文件之后写入；`final` 只在整批结束时为 true。
17. 取消：进行中的分片被 `AbortMultipartUpload`。
18. 本机时间偏差 10 分钟：照常工作；偏差更大时提示校对时间。
19. Windows：长路径、保留名、大小写不敏感文件系统下的重名。
20. HEIC 解码后按设置输出。
21. 没导入配置时，所有现有功能和现在完全一致。

## 8. 不做（v1）

- 项目资料清单、投放区、任何项目概念。
- 账号、登录、多用户。
- 远端文件的列出、删除、撤回（凭证本来就不允许）。
- 版本化（同一路径内容变了就覆盖）。
- 自动更新。
- 服务端逻辑（签发凭证、判断资料齐不齐、通知项目经理）。

## 9. 需要你来定的

- 视频抽帧用哪种实现（内置 ffmpeg / 系统 API），连同许可证。
- journal 用 SQLite 还是 JSON Lines（要支持崩溃后一致、能跨重启恢复）。
- 钥匙串库的选择（macOS 和 Windows 各一）。
- `x-amz-checksum-sha256` 在目标端是否生效，实测后记录在代码注释里。
- 如果大陆网络访问 R2 不稳定，是否需要备用的上传地址（配置里加一个可选的 `fallbackCredentialsUrl`）；先别做，只留好扩展点。

## 10. 实现现状（v1 第一版）

本节记录实现时做的决定、与上文的出入，以及还没做的部分。出入处以本节为准，上文未改。

### 已实现

- F1–F12 的 Go 侧逻辑都在 `internal/push`，`pushservice.go` 负责接到界面上。前端只负责渲染 Go 推过来的快照和事件。
- 验收第 2–9、11–13、15–18、20 条有自动化测试（`go test ./internal/push/`）。测试用的假 S3 只实现 §5 列出的 5 个写操作，其余请求一律记为违规；它还会在服务端重算 SigV4 签名，并且在每份批次清单到达时核对：清单里列的对象是否都已经存在。
- 本地联调：`cmd/push-devserver`（§6）。

### §9 的决定

| 问题 | 决定 |
| --- | --- |
| 视频抽帧 | 用 `ffmpeg` / `ffprobe` 子进程，只读本机文件、不联网。查找顺序：先找可执行文件旁边，再找 `PATH`；都找不到时，视频列为跳过（`unsupported`，说明里写「这个版本还不能处理视频（原片不会上传）」）。`.app` 内置 FFmpeg 9.0.2 的 LGPL-2.1-or-later 构建（`scripts/build-ffmpeg.sh`，静态、只开抽帧需要的解封装器 / 解码器和 PNG 输出，架构跟随 app 二进制），放在 `Contents/Resources/`；版本、许可证、源码获取方式见 README「License」。不支持 AV1。 |
| journal | JSON Lines，每次追加都 fsync；启动时重放并压缩。崩溃时写了一半的最后一行会被忽略。一个连接一份，目录由连接身份推出（配置的 label + credentialsUrl；手填 S3 则是 endpoint + bucket + 前缀），所以启动时不联网也能找到未完成的批次。 |
| 钥匙串 | `github.com/zalando/go-keyring`：macOS 用 Keychain，Windows 用凭据管理器。 |
| `x-amz-checksum-sha256` | 单次 PUT 会带上；分片只靠已签名的 `x-amz-content-sha256`，S3 / R2 会据此核对收到的字节。**还没在 R2 上实测**；`x-amz-meta-sha256` 每个对象都写。 |
| 备用地址 | 没做。所有凭证都经由 `CredentialSource` 接口取得，以后加 `fallbackCredentialsUrl` 只需要新增一个实现。 |

### 与上文的出入

- **去重身份**是（远端位置 `endpoint/bucket/prefix`，键，原图 SHA-256，压缩参数），比 F8 多了「远端位置」：服务端改了前缀后会重新上传，而不会被误判成已经传过。
- **键名长度**统一按「前缀最长 128 字节」来预留，而不是按实际前缀算，所以扫描完全不需要联网，同一批拖入总是得到同样的键名。凭证接口返回的 `prefix` 必须 ≤ 128 字节，超过的话 PicPress 会拒绝使用。
- **图片的键名**：输出格式要压缩完才知道（「智能」格式下尤其如此），所以同一文件夹里同名不同扩展名的图片（`a.jpg`、`a.png`）在扫描时就按重名处理，后一个改成 `a (2)`。重名比较之前统一做 NFC 规整和大小写折叠。视频的 `.frames/` 目录如果和真实文件夹撞名，改名的是视频，真实文件夹保持原样。
- **批次清单**：
  - 每一份清单只列出**和上一份相比新增**的结果（增量），服务端要把同一个 `batchId` 的各份清单按 `seq` 合起来看。
  - `files` 列出每一个上传的对象，视频的抽帧、联系表和 `meta.json` 也在里面。`videos` 只列本批真正上传了的视频。
  - `skipped` 新增字段 `renamedTo`（仅 `name-conflict-renamed` 时出现）；`skipped` 只在一个批次的第一份清单里出现。
  - 新增 `canceled: true`：取消时写最后一份清单，`final: true` 同时带上这个字段。
  - 「重试失败项」沿用原来的批次，所以同一个批次可能出现不止一份 `final: true`，以 `seq` 最大的那份为准。
- **暂停、退出和取消**：用户点「暂停」后，重开应用仍保持暂停；直接退出、强退或断电，重开后自动续传；取消会对未完成的分片上传发 `AbortMultipartUpload`。
- **凭证刷新**：剩余有效期少于「5 分钟」和「有效期的一半」中较小的那个，就提前换新。否则 30 秒有效期的凭证会在每个请求前都去换一次。
- **断网**：请求完全没有收到响应时，先试着和 S3 / 凭证地址建立一次 TCP 连接（这一步不算对存储桶的读操作）。连得上，就算这个文件的一次失败，计入重试次数；连不上，所有文件一起进入「正在等待网络」，不计入重试次数，网络恢复后继续。

### 还没做

- 「准备上传」面板里的**预估压缩后大小**：要估准只能先压一遍，目前只显示原始大小。
- 设置里的**并发数和限速**：引擎已经支持（`Concurrency`、`BytesPerSec`），界面还没加。
- **云盘占位文件**的专门识别：目前读不到时统一记为 `read-error`，并提示「如果它在云盘里，请先下载到本机」。
- **Windows 版**：代码能交叉编译（`GOOS=windows go vet` 通过），但安装包、文件关联、Authenticode 签名、内置 ffmpeg 都还没做。macOS 的文件关联已经写进 `Info.plist`；Developer ID 签名和 notarize 没做。
